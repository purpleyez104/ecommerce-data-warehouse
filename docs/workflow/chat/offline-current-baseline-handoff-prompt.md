请基于本对话中已经真实发生的离线链路建设过程，整理截至当前时刻的离线链路 Current Baseline，并生成一份可以直接交给 ChatGPT Work 用于维护 ecommerce-data-warehouse 项目目录的标准交接包。

核心原则

这次任务不是继续开发，也不是重新规划项目，而是建立“截至当前的唯一可信事实基线”。

必须严格区分：

VERIFIED：本对话中有明确命令、输出、文件或验收结果证明已经真实成功。

DOING：已经开始执行，目前正在推进，但还没有形成完整验收闭环。

DESIGNED：已经明确设计或确认方案，但尚未实际执行验证。

HISTORY：旧方案、旧阶段、旧脚本、已经被新设计替代的内容、失败版本、来源不明确的内容。

UNKNOWN：当前证据不足，不能判断是否真实投入使用。

禁止把“规划过”“生成过文件”“讨论过”“理论上应该存在”的内容写成 VERIFIED。

特别注意

当前真实工程事实优先于旧 plan.md、旧 M1/M2/M3 阶段规划和早期设计文档。

如果后续实际操作已经改变了早期设计，以后期真实验证结果为准。

已经被指标重设计、业务设计重构或技术方案更新覆盖的旧方案，只能放入 HISTORY。

不要求补齐所有历史调试命令，只保留能够证明最终状态的关键证据。

不修改任何项目文件，只生成交接信息。

不为了“看起来完整”而猜测文件名、路径、脚本内容或执行结果。

如果同一个功能存在多个版本，明确指出最终采用哪个版本，以及其他版本为什么归入 HISTORY。

当前离线链路以实际已经跑通的 DataX、HDFS/Hive、Spark SQL 等结果为基础梳理，不要重新从最早计划推导进度。
