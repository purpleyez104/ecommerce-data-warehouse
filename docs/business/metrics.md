# 电商最终指标体系 V2.1｜统一口径与验收规范

> 文档状态：`draft / candidate`；在 V2.0 基础上与 V2 数据规格及实施方案候选稿对齐，待细化指标和稳定发布 ID 尚未冻结。
> `TR / TF / PR / US / RF / MK` 为指标检索编号。
> 已冻结业务口径继续保留；未冻结的公式、分母、窗口继续标记为 `待细化`。
> 本文件负责定义“算什么、怎么算、什么时间口径、如何去重和修订”，不负责定义 DWD / DWS / ADS 的完整物理字段。

---

# 1. 全局指标契约

| 属性      | 统一规则                                                                                                        |
| ------- | ----------------------------------------------------------------------------------------------------------- |
| 业务模式    | 自营商城；一期覆盖订单、支付、基础退款、订单券、商城整体漏斗                                                                              |
| 时区与自然日  | `Asia/Shanghai`；当地 00:00:00 开始新统计日                                                                          |
| 事件时间    | 下单、支付成功、退款成功、注册、行为发生、券状态变化等使用各自业务发生时间                                                                       |
| 记录/采集时间 | `recorded_at`、`ingest_time` 等用于增量发现、迟到识别和延迟监控，不直接替代业务时间                                                     |
| 去重      | 订单按 `order_id`；订单明细按 `order_item_id` 或 `(order_id, sku_id)`；支付按唯一成功资金业务；退款按申请及成功资金执行；券按实例/事件；行为按 `event_id` |
| 迟到/修订   | 取消回冲原创建日有效 GMV；退款归属退款成功日，同时影响订单群组累计净额；可靠身份修订可以触发受影响窗口重算                                                     |
| 截止点     | 对会随取消、退款、迟到事件、观察窗口等变化的指标保留 `as_of_time` 或等价截止点                                                              |
| 计算版本    | 需要修订、回算或批量重算的指标保留 `calculation_version`、`batch_id` 或等价审计版本                                                  |
| 身份版本    | UV、活跃用户、群组漏斗等身份敏感指标保留 `identity_version` 或等价身份映射版本                                                          |
| 离实时     | 离线与实时共享业务主键、事实粒度和指标定义；实时 ≤5 分钟、T+1 次日 10:00 前均为设计验收目标，不能提前当作实测性能                                            |
| 金额      | 物理存储使用整数分；金融值不使用 FLOAT / DOUBLE                                                                             |
| 反重复计算   | 当前状态和状态事件属于同一业务事实的不同表示，不能重复汇总                                                                               |

指标定义状态：

```text

TBD
指标方向存在，但关键分母、窗口或判定规则仍未冻结

REFERENCE
```


# 2. 交易与资金（TR）

| 编号    | 指标             | 业务定义与公式                                | 时间归属 / 粒度 / 去重与过滤      | 取消/退款处理               |
| ----- | -------------- | -------------------------------------- | ---------------------- | --------------------- |
| TR-01 | 全部下单金额         | `Σ 创建订单 payable_amount`                | 创建日；订单粒度；`order_id` 一次 | 后续取消仍保留创建事实           |
| TR-02 | 有效 GMV（正式 GMV） | `Σ 截至 as_of_time 未取消订单 payable_amount` | 原订单创建日；订单粒度            | 取消回冲原创建日；退款不直接扣 GMV   |
| TR-03 | 商品原价交易额        | `Σ 订单 gross_amount`                    | 创建日；订单粒度               | 与券后 GMV 区分            |
| TR-04 | 订单优惠金额         | `Σ 订单 discount_amount`                 | 创建日；订单粒度               | 原价－优惠＝应付，禁止订单头与明细重复汇总 |
| TR-05 | 创建订单数          | `COUNT(DISTINCT order_id)`             | 创建日                    | 保留已取消订单               |
| TR-06 | 有效订单数          | 截至截止点未取消的订单数                           | 原创建日                   | 取消回冲原创建日              |
| TR-07 | 成功支付金额         | `Σ 每订单唯一有效 SUCCESS 资金金额`               | 支付成功日                  | 失败及重复通知排除；不扣退款        |
| TR-08 | 成功支付订单数        | 存在唯一有效支付成功的去重订单数                       | 支付成功日                  | 支付重试不增加订单数            |
| TR-09 | 下单用户数          | 创建订单的去重统一身份                            | 创建日                    | 身份版本按需要保留             |
| TR-10 | 支付用户数          | 有效成功支付的去重统一身份                          | 支付成功日                  | 失败尝试排除                |
| TR-11 | 成功退款金额         | 唯一成功退款申请对应的实际成功资金金额                    | 退款成功日                  | 失败尝试不计；禁止事件与资金事实双算    |
| TR-12 | 当期资金净流入        | `当期成功支付金额－当期成功退款金额`                    | 各自成功发生日                | 现金流视角，不等于 GMV         |
| TR-13 | 订单累计净支付        | `订单群组累计成功支付－累计成功退款`                    | 订单群组 + `as_of_time`    | 跨日退款修订原订单群组累计净额       |
| TR-14 | 同批订单支付转化率      | 同一创建订单群组在有效窗口内成功支付订单数 / 群组创建订单数        | 创建订单群组；同 order_id      | 不使用“当日支付数 / 当日下单数”替代  |

## 2.1 商品维度切片规则

交易指标允许按照：

```text
SKU
SPU
Category
Brand
```

等商品维度切片。

历史交易不得直接关联商品当前状态。

正式 V2 采用：

```text
事实发生时间
        ↓
dim_product_zip.start_time <= fact_time
        ↓
fact_time < dim_product_zip.end_time
        ↓
匹配 product_sk
```

获得交易发生时有效的：

```text
SKU
SPU
Category
Brand
```

订单明细仍必须保存属于交易事实本身的：

```text
quantity
成交单价
gross_amount
allocated_discount_amount
payable_amount
```

不能用商品当前价格重新计算历史订单金额。

订单级金额按 SKU 等维度拆分时，必须使用订单明细分摊金额，不得直接把订单头金额 JOIN 到多行明细后重复累计。

# 3. 流量与转化（TF）

## 3.1 Canonical Behavior Event Type

V2 行为事件正式统一使用：

```text
PAGE_VIEW
PRODUCT_EXPOSURE
PRODUCT_CLICK
ADD_CART
REMOVE_CART
```

禁止在正式 Contract 中继续混用：

```text
VIEW
EXPOSURE
CLICK
```

等语义不完整名称。

| 编号    | 指标         | 统计对象 / 定义                     | 时间归属与去重                          | 边界                      |
| ----- | ---------- | ----------------------------- | -------------------------------- | ----------------------- |
| TF-01 | PV         | 合法 `PAGE_VIEW` 事件数            | `event_time` 所属业务日；`event_id` 去重 | 不等于用户数                  |
| TF-02 | UV         | 当日发生有效访问的统一身份数                | 行为事件日；可靠身份映射版本去重                 | 无可靠映射时保持匿名              |
| TF-03 | 商品曝光量      | 合法 `PRODUCT_EXPOSURE` 事件数     | `event_time`；`event_id` 去重       | 同一身份可以多次曝光              |
| TF-04 | 商品点击量      | 合法 `PRODUCT_CLICK` 事件数        | `event_time`；`event_id` 去重       | 与曝光分开                   |
| TF-05 | 加购行为量 / 人数 | `ADD_CART` 事件数 / 去重加购身份数      | 加购事件时间                           | 不把 cart_item 当前数量当作行为次数 |
| TF-06 | 移除购物车量     | `REMOVE_CART` 事件数             | 行为时间；`event_id` 去重               | 不等于负销量                  |
| TF-07 | 每日经营漏斗     | 自然日内分别统计 PV/UV、曝光、点击、加购、下单、支付 | 各阶段按各自业务事件日                      | 不是同群组转化                 |
| TF-08 | 7 日同群组漏斗   | 入口身份群组按事件顺序观察后续阶段             | 入口起始后 7×24h；身份群组内去重              | 商城整体首期不强制所有阶段同 SKU      |

两种漏斗分别保留：

```text
每日经营漏斗
7 日同群组漏斗
```

不得混为同一个转化率。

# 4. 商品（PR）

| 编号    | 指标        | 公式/对象                             | 时间/去重/过滤      | 补充                                     |
| ----- | --------- | --------------------------------- | ------------- | -------------------------------------- |
| PR-01 | 下单件数      | `Σ order_item.quantity`           | 创建日；订单明细一次    | 必须明确全部/有效子口径                           |
| PR-02 | 商品销量（主口径） | `Σ 有效成功支付订单的 order_item.quantity` | 支付成功日；同一明细一次  | 退款另用 PR-03                             |
| PR-03 | 商品退款件数    | `Σ 成功退款申请明确记录的 refund_quantity`   | 退款成功日；申请去重    | `refund_quantity=NULL` 的金额补偿不计件数       |
| PR-04 | 商品销售金额    | 成功支付订单明细券后分摊应付金额之和                | 支付成功日；明细去重    | 商品属性使用交易发生时匹配到的 `dim_product_zip` 历史版本 |
| PR-05 | 商品排行      | 对明确命名的金额或数量指标排序                   | 与原指标保持相同时间和粒度 | TopN 并列规则在 Serving 设计中冻结               |

SKU 为交易明细自然粒度。

SPU、类目、品牌等历史属性通过：

```text
事实时间
→ dim_product_zip
```

取得，不使用当前商品属性回算历史交易。

| 衍生指标        | 必要事实                              | 禁止错误           |
| ----------- | --------------------------------- | -------------- |

# 9. 历史修正、实时与离线验收

## 9.1 指标结果元数据

不是所有指标结果都强制拥有完全相同的版本字段。

根据指标性质使用：

```text
业务日期
或
cohort_date
```

对可能被未来事件修订的指标：

```text
as_of_time
```

对批量回算和修订：

```text
calculation_version
或
batch_id
```

对身份敏感指标：

```text
identity_version
```

如果采用统一指标结果表，可额外记录：

```text
metric_id
```

---

## 9.2 历史修正规则

1. 创建当日订单进入 TR-01 与 TR-02。
2. 后续取消只回冲原创建日 TR-02 / TR-06，不回冲 TR-01。
3. 退款按退款成功日进入 TR-11 / TR-12。
4. 同笔退款同时影响原订单群组截至指定截止点的 TR-13、RF-05/06。
5. GMV 不因退款直接扣减。
6. 初始快照、Binlog 与 Behavior Replay 必须使用统一业务键和去重规则。
7. 同一支付或退款事实只能有一个权威聚合输入。
8. 实时可以先产生暂定结果，补偿/回算后与 T+1 在统一截止点对账。
9. Behavior 窗口使用 `event_time`。
10. `ingest_time` 只用于延迟和迟到识别。
11. 迟到事件按原业务时间回补，不强行归入到达日。
