# 指标口径

版本：`0.2-draft`
状态：`P1_METRIC_030` 的基础业务公式已确认；其余正式指标仍待定义

## 使用方式

每个正式指标在实现前都应至少记录以下信息：

| 字段 | 说明 |
| --- | --- |
| `metric_id` | 稳定且唯一的指标编号，例如 `M-001` |
| 名称 | 面向业务的中文名称 |
| 业务定义 | 统计对象、包含与排除规则 |
| 粒度与维度 | 一行或一个结果对应的业务范围 |
| 公式 | 分子、分母、去重规则和零分母处理 |
| 时间语义 | 事件时间、统计周期和时区 |
| 来源 | 源表字段及 ODS/DWD/DWS 血缘 |
| 验证样例 | 固定输入、预期输出和边界场景 |
| 状态 | `draft`、`implemented` 或 `verified` |

## 口径规则

- 先确认业务定义和粒度，再编写 SQL。
- 比率必须同时保留分子和分母；平均值必须说明加权方式。
- 同一指标只维护一个正式口径；更名或公式变化必须保留变更记录。
- 指标状态为 `verified` 前，必须在固定样例和真实引擎中完成结果核对。

## 已确认的基础业务语义

以下内容由 `DR-009` 至 `DR-012` 确认，是后续指标口径的共同输入；除 `P1_METRIC_030` 的基础公式外，不等于其他指标公式已经完成：

- 新访客与老访客按 `visitor_id` 的首次访问日期和业务日期比较，两类互斥。
- 会话以 30 分钟无活动或跨 `Asia/Shanghai` 自然日为切分边界，渠道归属取会话首次进入渠道。
- 新增用户按注册日期识别；活跃用户要求业务日期内至少一次带 `user_id` 的访问、加购、下单或支付行为。
- 回流用户要求此前活跃、连续 7 个完整自然日未活跃，并在业务日期再次活跃；新增用户与回流用户互斥，活跃用户可以包含两者。
- 新增下单人数和新增支付成功人数分别依据个人首次有效订单日期和首次成功支付日期；各过程按自身事件时间所属的 `Asia/Shanghai` 业务日期归属。
- 商品指标以 Brand → SPU → SKU 和三级 Category 为基础层级；SKU 是浏览、加购和交易的最小商品单位，订单指标使用下单时保存的商品归属快照。
- 加购人数按事件发生时的主体去重：已登录使用 `user_id`，匿名使用 `visitor_id`，不追溯合并登录前行为；具体统计窗口仍待指标口径确认。
- 订单以一次结算形成的订单头为基础业务对象，一种 SKU 对应一条订单明细；金额仅使用 `CNY`、保留两位小数并使用 `HALF_UP`，品牌、Category、SPU 相关订单指标的有效状态和最终公式仍待后续确认。
- 支付成功人数按 `paid_at` 所属业务日期对 `user_id` 去重；一个订单最多一笔成功支付，重复回调不重复计数或改变首次成功时间。
- 退单数以状态为 `COMPLETED` 的退单业务单为基础，不按退款流水计数；商品归属使用原订单明细快照。
- 部分退款与多次退款保留独立资金记录，累计成功退款金额按订单明细应付金额和累计完成退货数量计算，不得超过成功支付金额；订单类指标是否扣减后续退款仍待各指标口径确认。
- 业务日期使用 `Asia/Shanghai`，业务时间保留毫秒精度；指标必须使用对应事件时间，不得使用 `create_time`、`update_time`、数据到达时间或任务执行日期代替。

## 已确认的正式指标基础公式

### P1_METRIC_030 优惠券补贴率

| 项目 | 已确认口径 |
| --- | --- |
| 状态 | `draft`；业务公式已确认，来源字段、分层血缘、固定样例和真实引擎结果尚未完成 |
| 业务含义 | 成功支付订单在支付业务日期获得的优惠券毛补贴占商品原价金额的比例 |
| 统计日期 | 首次成功支付 `paid_at` 对应的 `Asia/Shanghai` 业务日期 |
| 分子 | 统计日期内成功支付订单的优惠券优惠金额之和 |
| 分母 | 同一批成功支付订单的商品原价金额之和 |
| 公式 | 优惠券优惠金额之和除以商品原价金额之和 |
| 退款处理 | 后续退款不追溯修改支付日毛补贴率；净补贴率不纳入 V1 |
| 零分母 | 输出 `0`，同时在 DWS 保留分子和分母 |
| 精度与舍入 | 比率保留 4 位小数，百分比展示保留 2 位小数，使用 `HALF_UP` |
| 优惠券范围 | 仅包含合法锁定并随订单成功支付转为 `USED` 的固定金额优惠券 |
| 待补内容 | M2.2 来源字段，M2.3 固定样例，Milestone 4-5 分层血缘与 SQL，真实引擎验收 |

身份关联、登录前事件不回写、跨日会话切分、金额分摊和优惠券状态机等完整规则以正式业务设计文档 `docs/milestone-2-business-design.md` 为准。`P1_METRIC_001` 至 `029` 的完整公式仍待后续指标评审；`P1_METRIC_030` 也必须在来源字段、固定样例、分层血缘和真实引擎核对完成前保持 `draft`。
