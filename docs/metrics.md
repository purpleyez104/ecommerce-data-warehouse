# 电商最终指标体系 V2.0｜统一口径与验收规范

> 文档状态：根据本对话已确认的第二阶段交易资金指标 V1.0 + 流量/商品/用户/退款/营销决策整理；2026-09-18。**以下 `TR/TF/PR/US/RF/MK` 编号是本文档的检索编号，不宣称是旧对话中原指标编号。**
> 已确认口径优先；对未在对话中精确定义的公式/分母/归因细节标记 `待细化`，不以行业默认口径补成“已确认”。
> 关联：[业务基线](business/business-baseline-v2.md) · [逻辑模型](source/logical-model-v2.md)。
>
> 当前实现状态：本文记录业务口径基线；检索编号尚未确认为对外稳定发布 ID，且尚无对应 DWS/ADS SQL、完整字段血缘、固定数据结果或真实引擎验收，因此不得描述为 `implemented` 或 `verified`。

## 1. 全局指标契约

| 属性 | 统一规则 |
|---|---|
| 业务模式 | 自营商城，第一期覆盖订单、支付、基础退款、订单券、商城整体漏斗 |
| 时区与自然日 | `Asia/Shanghai`；当地 00:00:00 开始新统计日 |
| 事件时间 | 按下单、支付成功、退款成功、注册、行为发生、券状态发生等各自业务时间；记录/采集时间用于延迟监控 |
| 去重 | 订单 `order_id`；订单明细 `order_item_id` 或 `(order_id,sku_id)`；成功支付资金尝试 ID + 有效订单；退款成功申请/资金尝试 ID；券实例与券事件 ID；行为 `event_id`；访客统一身份键（可靠映射版本） |
| 截止点 | 每个历史指标须记录 `as_of_time`（统计截止时间）与必要的 `identity_version`/`calculation_version`；不是一劳永逸的不可修改自然日数据 |
| 迟到/修订 | 取消修正**原创建日** GMV；退款归属真实退款成功日，并影响原订单群组累计净额；可靠身份修订按指定版本回算受影响窗口 |
| 离实时 | 事件和指标共享业务主键、事实粒度、指标口径；实时 ≤5 分钟、T+1 次日 10:00 前均为验收目标，未宣称压测达标 |
| 金额 | 来源物理候选方案用整数分；本文展示元仅为可读性；金融值不使用 FLOAT/DOUBLE |
| 反重复计算 | 状态当前值和状态事件是两种表示，不能同时汇总同一交易事实 |

## 2. 交易与资金（TR）

| 编号 | 指标 | 业务定义与公式 | 时间归属 / 粒度 / 去重与过滤 | 取消/退款处理 |
|---|---|---|---|---|
| TR-01 | 全部下单金额 | `Σ创建订单的 payable_amount`，不因之后取消删除“创建事实” | 创建日；订单粒度；按 order_id 一次 | 保留被取消订单 |
| TR-02 | 有效 GMV（正式 GMV） | `Σ截至 as_of_time 未取消订单的 payable_amount` | 原**订单创建日**；订单粒度，按 order_id 去重 | 取消后回冲原下单日；退款不作为订单取消，不直接从 GMV 扣除 |
| TR-03 | 商品原价交易额 | `Σ订单 gross_amount` | 创建日；订单粒度；只按订单头计一次 | 属于原价金额，与券后 GMV 区分；是否另设有效原价子口径需显式命名，不与此混淆 |
| TR-04 | 订单优惠金额 | `Σ订单 discount_amount` | 创建日；订单粒度；按有效性过滤条件与对应报表一致 | 原价－优惠＝应付；不要叠加明细分摊与订单金额 |
| TR-05 | 创建订单数 | `COUNT(DISTINCT order_id)`，订单创建事实 | 创建日；不以支付尝试条数替代 | 保留已取消订单；有效订单数另列 TR-06 |
| TR-06 | 有效订单数 | `COUNT(DISTINCT order_id)` 且截至截止时点未取消 | 原创建日；订单粒度 | 取消后回冲原创建日 |
| TR-07 | 成功支付金额 | `Σ每订单唯一有效 SUCCESS 资金交易金额` | 支付成功日；有效订单/成功资金业务去重，过滤失败及重复通知 | 不扣退款；作为资金净额的支付侧输入 |
| TR-08 | 成功支付订单数 | `COUNT(DISTINCT order_id)` 且有唯一有效支付成功 | 支付成功日；订单粒度 | 支付重试不增加订单数 |
| TR-09 | 下单用户数 | 发生创建订单的去重用户/可靠身份 | 创建日；身份去重、指定身份版本 | 群组口径与简单日人数分开 |
| TR-10 | 支付用户数 | 发生有效成功支付的去重用户/可靠身份 | 支付成功日；身份去重 | 失败尝试排除 |
| TR-11 | 成功退款金额 | `Σ唯一成功退款申请对应的实际成功资金金额` | 退款成功日；按申请及资金业务去重 | 失败尝试不入账；不与退款事件双加 |
| TR-12 | 当期资金净流入 | `当期成功支付金额－当期成功退款金额` | 同一期间内支付与退款各自成功日；资金流水视角 | 可能涉及不同订单日期，**不是** GMV |
| TR-13 | 订单累计净支付 | `指定订单群组截至 as_of 的成功支付总额－累计成功退款总额` | 按订单群组归属（如原创建日）+截止点；订单去重 | 跨日退款回修原订单群组截至截止点的净支付 |
| TR-14 | 同批订单支付转化率 | `创建订单群组中在规定窗口内成功支付的订单数 / 同群组创建订单数` | 订单创建群组；支付必须关联同一订单；支付受 15 分钟有效期业务约束 | 不使用“当日支付数/当日下单数”冒充同群组转化 |

**统计对象与维度**：TR-01~08 默认订单或支付资金事实；TR-09/10 为统一身份；TR-11~13 使用退款申请和唯一成功执行记录。允许按自然日/周/月、订单原始 SKU/类目/品牌快照、用户和券使用情况等切片；订单级金额按 SKU 切片必须使用订单明细分摊应付，不直接把订单头金额 JOIN 多行明细。非加性比率（如 TR-14）必须先合并分子/分母再求比。

## 3. 流量与转化（TF）

| 编号 | 指标 | 统计对象 / 定义 | 时间归属与去重 | 边界 |
|---|---|---|---|---|
| TF-01 | PV | 计数合法 `page_view` 事件 | 行为事件时间日；以 event_id 去重 | 不等于用户数 |
| TF-02 | UV | 当日发生有效访问的统一访客人数 | 按可靠身份映射版本去重；无法确认归属保持匿名 | 允许版本化历史修订 |
| TF-03 | 商品曝光量 | 合法 `product_exposure` 事件数 | 曝光发生时间；event_id 去重 | 同一访客可多次曝光 |
| TF-04 | 商品点击量 | 合法 `product_click` 事件数 | 点击时间；event_id 去重 | 与曝光分开 |
| TF-05 | 加购行为量/人数 | 合法 `add_cart` 事件数 / 去重加购身份数，分别命名 | 加购时间；事件或身份分别去重 | 不把 `cart_item` 当前数量当行为次数 |
| TF-06 | 移除购物车量 | 合法 `remove_cart` 事件数 | 行为时间；event_id 去重 | 与负销量不同 |
| TF-07 | 每日经营漏斗 | 分别统计某自然日 PV/UV、曝光、点击、加购、下单、支付阶段 | 各阶段按**各自事件日**与各自已定义人数/次数粒度 | 期间比值不是同群组转化率 |
| TF-08 | 7 日同群组漏斗 | 首次合规入口事件形成同一批身份，按事件时间严格顺序识别阶段 | 入口起始后 7×24h；同一身份在群组去重 | 商城整体首期无需所有阶段同 SKU；下单/支付同 order_id |

**漏斗使用约束**：两套漏斗同时保留、分别命名；按同批用户计算各步转化率时需固定入口人数和所比较阶段，原则是对应阶段去重人数 ÷ 同一入口群组人数或前一步同群组人数，并在报表标记所采用的分母。对话未冻结每个细分“阶段转化率”的固定分母名称，暂列实现前待细化，禁止混用。

## 4. 商品（PR）

| 编号 | 指标 | 公式/对象 | 时间/去重/过滤 | 补充 |
|---|---|---|---|---|
| PR-01 | 下单件数 | `Σ订单明细 quantity`，订单创建事实 | 创建日；每明细一次 | 取消如何呈现应标注“全部”或“有效”子口径，勿混用 |
| PR-02 | 商品销量（主口径） | `Σ有效成功支付订单中订单明细 quantity` | 支付成功日；同一订单明细只计一次 | 退款另设 PR-03，不将金额退款等同退款件数 |
| PR-03 | 商品退款件数 | `Σ成功退款申请中明确记录的 refund_quantity` | 退款成功日；申请去重 | 空数量的金额补偿不计件数 |
| PR-04 | 商品销售金额 | 成功支付订单明细**券后分摊应付**之和 | 支付成功日；按明细去重 | 用成交时 SKU/SPU/类目/品牌快照，禁止用现价重算 |
| PR-05 | 商品排行 | 对已命名的金额或数量指标排序 | 指标同口径时段和粒度 | TopN及并列名次规则在 Serving 技术设计阶段明确 |

SKU 为交易粒度；SPU、类目、品牌可由成交快照聚合。首期不实施要求所有行为阶段同 SKU 的商品级漏斗。

## 5. 用户（US）

| 编号 | 指标 | 业务定义 | 时间及去重 | 注意 |
|---|---|---|---|---|
| US-01 | 注册新增用户数 | 当日成功注册用户去重数 | `registered_at` 日，user_id | 与首购分开 |
| US-02 | 首购用户数 | 首次成功支付发生在该日的用户数 | 首次有效 `paid_at` 日，用户 ID/可靠身份 | 不是首次下单 |
| US-03 | 活跃用户数 | 当日发生已定义有效行为的统一身份数 | 行为日、身份版本；用户/匿名访客统一 | “有效行为”的事件集合在报表上明确，当前可使用已列举五种行为 |
| US-04 | 下单用户数 | 与 TR-09 同义**引用**，不重复建设独立计算事实 | 创建日，统一身份 | 依赖 TR-09 |
| US-05 | 支付用户数 | 与 TR-10 同义**引用** | 支付日，统一身份 | 依赖 TR-10 |
| US-06 | 复购率 | 已列入分析方向但**本对话未冻结观测窗口、分母与复购事件** | — | `待细化`：禁止默认为“购买≥2次人数/支付人数”已经确认 |

## 6. 退款与售后（RF）

| 编号 | 指标 | 业务定义/公式 | 时间/粒度 | 边界 |
|---|---|---|---|---|
| RF-01 | 退款申请数 | 去重退款申请数量 | 申请时间日；refund_request_id | 失败申请依然属于申请事实 |
| RF-02 | 成功退款申请数 | 最终成功退款的去重申请数 | 最终成功时间日；refund_request_id | 一申请多尝试至多成功一次 |
| RF-03 | 成功退款金额 | **引用 TR-11** | 退款成功日 | 防双算 |
| RF-04 | 退款件数 | **引用 PR-03** | 明确成功数量的退款申请 | 不按金额估件数 |
| RF-05 | 同批订单累计金额退款率 | `截至同一 as_of，同订单创建群组累计成功退款金额 / 该群组成功支付金额` | 订单创建日群组；保持同一截止点 | 分母为零时不定义比率；跨天退款回修群组 |
| RF-06 | 30 日标准化群组退款率 | `创建后 30×24h 内的群组成功退款金额 / 同群组成功支付金额`，分子分母按同一群组及规定可观察截止点 | 订单创建日群组，成熟后发布完整窗口结果 | 未成熟群组标暂定；精确的分母资金截点在指标实现前审核 |
| RF-07 | 部分退款比例 | 原讨论列入分析方向，但**部分的判定单位及分母未单独冻结** | — | `待细化`，勿当已确认口径 |

## 7. 营销（MK）

| 编号 | 指标 | 统计定义 | 时间/去重 | 说明 |
|---|---|---|---|---|
| MK-01 | 优惠券领取数 | 券实例成功发放/领取记录数 | 领取/发放事件日；coupon_id 去重 | 模板与实例分开 |
| MK-02 | 优惠券锁定数 | 独立有效 LOCK 状态事件数 | 锁定发生日；event_id 去重 | 同券合法释放后再锁应有不同事件 |
| MK-03 | 优惠券核销数 | 有效 USE/USED 券实例数 | 支付成功核销时间；coupon_id 去重 | 重复通知不重复核销 |
| MK-04 | 优惠券释放数 | 有效 UNLOCK/RELEASE 事件数 | 释放日；事件去重 | 已过期释放转 EXPIRED |
| MK-05 | 优惠金额 | `Σ真实用券支付订单的订单折扣金额`，同时允许另报下单占用优惠额并明确命名 | 支付日（真实优惠消耗）或创建日（下单优惠展示），不得混为一项 | 使用订单头或明细分摊其中一个聚合路径 |
| MK-06 | 用券支付订单数 | 去重成功支付且有效使用券的订单数 | 支付成功日；order_id | 退款不返券，USED 不逆转 |

## 8. 依赖与数据需求

```text
可靠身份映射(有版本) ─→ UV / 活跃 / 7日群组漏斗
行为事件(event_id,time,visitor_id,user_id,session_id,type) ─→ PV/曝光/点击/加购/移除/漏斗
订单头(order_id,created_at,status,amounts) ─→ GMV/下单/订单群组
订单明细(order_id,sku_id,quantity,成交与优惠快照) ─→ 商品金额/销量/分类分析
支付尝试及事件(唯一成功资金ID,时间) ─→ 支付/首购/资金净流入
退款申请及资金成功(明细,金额,明确数量,成功时间) ─→ 退款/净支付/退款率
券实例及事件(领取/锁定/核销/释放时间) ─→ 营销
```

| 衍生指标 | 必要基础指标 | 避免的错误 |
|---|---|---|
| TR-02 GMV | 订单创建事实+取消事件+应付金额 | 按取消日扣减导致错归属 |
| TR-12 当期净流入 | TR-07 + TR-11 | 把退款回冲支付成功日现金流 |
| TR-13 累计净支付 | 同群组支付/退款 + as_of | 把当期现金流误称订单净销售 |
| TR-14 支付转化 | 创建订单群组+同单成功支付 | 日支付数/日下单数混群组 |
| TF-08 漏斗 | 事件顺序+身份版本+7日窗口 | 只做独立日比值 |
| RF-05/06 退款率 | 同群组支付/退款+观察截止点 | 不同年龄群组直接比 |
| MK-05 优惠金额 | 唯一用券订单+分摊守恒 | 订单头和明细重复相加 |

## 9. 历史修正、实时与离线验收

1. 每次结果保留 `metric_id`、业务日期/群组、`as_of_time`、`calculation_version`；身份敏感指标还保留 `identity_version`。修订输出应具备旧/新值、理由、影响窗口、执行批次。
2. 创建当日新增订单计入 TR-01/02；次日取消仅回冲原创建日 TR-02/TR-06，**不回冲 TR-01**。
3. 退款按退款成功日影响 TR-11/12，同笔退款再影响原订单群组截至对应截止时点的 TR-13、RF-05/06；GMV 不因退款自动扣除。
4. 初始快照与 Binlog/行为重放必须统一业务键、事件 ID 去重；同一支付和退款事实只选一个权威聚合输入。实时可先出暂定值，补偿/回算后与 T+1 在统一截止点对账。
5. 按 `event_time` 判定窗口，`ingest_time` 用于识别延迟；迟到事件按原时间回补，并保留修订，不强行归入到达日。

### 最小验收案例

| 案例 | 输入 | 预期 |
|---|---|---|
| 取消回冲 | D1 创建应付 100 元，D2 取消 | D1 TR-01 仍100，D1 TR-02 截至D2为0；D2 GMV不减100 |
| 优惠守恒 | 原价3400，券300，明细2735.29+364.71 | TR-02=3100；明细应付和3100 |
| 失败重试/重复通知 | P1 FAILED，P2 SUCCESS，P2成功回调重复 | 支付金额只记3100、支付订单数只记1 |
| 跨天退款 | D1 支付3100，D2成功退款364.71 | D1现金流3100，D2现金流-364.71；D1群组累计净支付2735.29 |
| 补偿退款 | 成功退款50元，未记录退款数量 | 退款金额+50，退款件数+0 |
| 身份修订 | 匿名 V 被可靠映射至 U | 指定身份版本重算受影响日 UV/漏斗，并留修订记录 |
| 群组漏斗 | D1 浏览、D2加购、D3下单及支付 | 可计入 D1入口7日群组；日经营漏斗仍按各自事件日 |
| 30日退款 | 订单创建不足30天即出报表 | RF-06 暂定/未成熟，不能标为完整30日 |

## 10. 明确未冻结的定义

复购率（US-06）、部分退款比例（RF-07）、券核销率（MK-07）的分母/窗口、细分漏斗阶段比率分母、标准化 30 日退款率精确的支付分母截点及支付完成临界时刻等，均应在开发相应指标前专项审查。本文件不将它们虚构为已经确认的原始业务口径。
