### 历史真实性

历史数据是后插入 MySQL 的、带历史业务时间的**模拟业务记录**；其 Binlog 发生时间是实际插入时刻，不是过去 90 天真实发生的 MySQL Binlog。CDC Snapshot 只能重现当前状态，历史事件来自 `biz_*_event` 表；用户旧状态变化只有生成期真实经过的 CDC 才可恢复，不能从最终 `biz_user` 快照推导全部历史。行为历史事件按 event_time 落 JSONL/发 Kafka，不自动执行 Kafka→HDFS 归档。

### 安全与数据修复

- V1 不执行 `DROP`、`TRUNCATE`、`FOREIGN_KEY_CHECKS=0` 或静默 upsert。
- 同批次重复启动被拒绝；部分完成时旧订单保留。需要持久状态表/断点游标与严格幂等恢复时进入 V1.1，而不是切新批次制造重复。
- 任何真实写入均需审核数据库用户权限、现有 CDC 运行状态及业务数据隔离。API、SQL、日志不输出密码。
- 两阶段跨 MySQL 与 Kafka 事务、Kafka 重复投递、跨表消费顺序、下游指标口径需专门处理。
